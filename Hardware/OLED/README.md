# 串口接收字符串并显示到 OLED

## 复用的驱动与硬件

本工程沿用现有 SSD1306 128×64 软件 I2C 驱动，不重新创建 OLED 模块。
探测 7 位地址 0x3C，无应答时探测 0x3D；地址应答不能识别屏幕控制器型号。
如果实际屏幕为 SH1106 或 128×32，需要进一步适配，不能只靠四针接口判断。

| 设备引脚 | STM32F103 |
| --- | --- |
| CH340 TXD | PA10（USART1 RX） |
| CH340 RXD | PA9（USART1 TX） |
| OLED SCL | PB3 |
| OLED SDA | PB4 |
| OLED VCC | 3.3V，须确认模块支持 |
| 两模块 GND | 与 STM32 共地 |

CH340 串口信号应为 3.3V TTL 电平。USART1 使用 115200、8N1、无流控。
SCL/SDA 需上拉至 3.3V，模块没有上拉时可各加约 4.7kΩ。
现有用户代码中 PC13、PB12 的初始化保留，与 OLED、USART1 引脚不冲突。

## 初始化和接口

`OLED_Init()` 完成以下步骤：

1. 更新系统时钟变量，开启 GPIOB、AFIO 时钟。
2. 调用 `GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)`，
   释放 PB3/PB4，保留 PA13/PA14 的 SWD，不可再使用 JTAG 下载。
3. 将 PB3/PB4 配置为开漏输出，等待上电稳定并恢复软件 I2C 总线。
4. 探测 OLED 地址，写入原有 SSD1306 页寻址初始化指令。
5. 调用 `OLED_Clear()` 清屏，再开启显示。

初始化只执行一次，不修改其他 GPIO 模式，也不启用硬件 I2C、DMA 或串口中断。
`OLED_Status`：0 未开始、1 初始化命令获应答、2 总线被拉低、
3 地址无应答、4 初始化指令未获应答。
`OLED_DetectedAddress` 记录探测到的 7 位地址。
初始化失败时 main 跳过显示，不阻止串口回显；没有自动重试或 LED 错误提示逻辑。

显示接口：

- `OLED_ShowString(x, page, str)`：单行 ASCII 字符串，超出右边界截断。
- `OLED_ShowReceived(str)`：覆盖页 2～7 的接收区，保留页 0 标题及页 1 空行。
- `OLED_Clear()`：全屏清除，初始化时使用，主循环不重复全屏清除。
- `OLED_ShowChinese()`、`OLED_ShowName()`：保留原接口，本次不调用。

驱动直接写 OLED 显存，不需要 `OLED_Update()` 或其他刷新函数。
ASCII 字库含 0x20～0x7E，每字 5×7 点阵加一列间距，占 6×8 像素。
接收区左侧留 6 像素，每行 20 字符，共 6 行，最多显示 120 字节；
超过显示范围则截断，不修改原接收数据。不支持通用中文或 UTF-8 解码，
不支持的字节逐字节显示为问号。原三个汉字的字库仍保留。
新内容写入时，同时将接收区其余位置写零，短字符串不会残留旧字符。

## main 数据流程

保留 PC13、PB12 初始化后，仅各调用一次 `USART1_Init()`、`OLED_Init()`。
OLED 初始化成功后显示固定标题 `UART RECEIVE`。
主循环每轮调用一次 `USART1_ReceiveString(buffer, maxLen)`，然后将同一个
`buffer` 依次交给 `OLED_ShowReceived(buffer)` 和 `USART1_SendString(buffer)`。
不重复接收，不修改 buffer，不添加指令解析，不改变回显内容。
主循环等待接收时不刷新 OLED；每次接收函数返回后才更新内容区。

## 原串口函数的边界限制（本次未修改）

`User/blue.c`、`User/blue.h` 原样保留，由用户维护。以下位置需要用户了解：

- `USART1_ReceiveString()` 中 `data == '\r' || data == '\n'`：只消费一个结束符。
  若发送 `\r\n`，剩余的换行会让下一次接收返回空字符串，并清空屏幕内容区。
  当前请只使用单个 LF（0x0A）或 CR（0x0D）结束，不要发送字面上的反斜杠和 n。
  如需兼容 CRLF，可自行在接收逻辑中加入跨调用的 CRLF 识别。
- `while (index < maxLen - 1)`：缓冲区满也会返回，并不保证已经收到完整一行。
  当前 buffer 为 32 字节，最多保存 31 字节；当正文正好达到 31 字节时，
  后续结束符会留到下一次接收。因此建议每条正文最多 30 字节，以单个 LF 结束。
  更长消息会被拆开显示/回显，不能视为一条完整消息。
  如需支持长行，可自行设计溢出标志及丢弃至行尾的接收策略。
- `USART1_ReceiveByte()`：无数据时阻塞，没有超时或接收错误处理。
- OLED 软件 I2C 写屏和 USART1 回显期间不会轮询接收，连续发送可能造成硬件溢出。
  请在启动初始化结束后发送一条消息，等到收到完整回显再发送下一条；
  当前结构不保证连续流或背靠背多条消息无丢失。

示例：电脑按文本模式发送 `hello` 加单个 LF，OLED 显示标题和 `hello`，
电脑收到原样的 `hello`（不自动追加换行）。再发送 `STM32` 加 LF，内容区更新为
`STM32`，标题不变。空行会清空接收内容区，标题仍保留。
